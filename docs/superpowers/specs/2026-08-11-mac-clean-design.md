# Mac Clean 设计说明

日期：2026-08-11
状态：已完成产品设计，等待书面规格审核

## 1. 产品目标

Mac Clean 是一款可签名、公证并直接分发的原生 macOS 菜单栏工具。它用于发现和清理应用缓存、日志、卸载残留、包管理器缓存，以及由包管理器明确认定的未使用依赖。

产品必须优先保证安全、透明和可追溯：确定可再生的缓存可以自动清理；卸载残留、依赖卸载和其他有风险的候选项必须由用户确认；不确定的项目只能报告，不能删除。

第一版面向 macOS 14 及以上系统，发布 Apple Silicon 与 Intel 通用版本，通过 Developer ID 签名、Apple 公证和 `.dmg` 安装包直接分发，不进入 Mac App Store。

## 2. 已确认的使用方式

- 应用常驻菜单栏，采用极简弹窗布局。
- 用户可以从菜单栏手动扫描。
- 应用每周进行一次后台扫描；错过计划时间时，在下次启动后补扫。
- 后台扫描只自动处理绿色候选项，并通过系统通知报告结果。
- 黄色候选项保留到详情窗口，等待用户逐项或批量确认。
- 首次使用时引导用户开启完全磁盘访问权限。
- 只有固定的受保护操作才请求管理员授权。

## 3. 风险分类和清理策略

### 3.1 绿色：允许自动清理

绿色项目必须同时满足以下条件：来源明确、内容可重新生成、目标位于允许的缓存或日志根目录、目标不属于正在运行的应用、执行前复查结果未发生变化。

第一版绿色项目包括：

- 已识别应用的缓存目录内容；正在运行的应用除外。
- 超过七天的可轮转应用日志；崩溃报告不自动删除。
- Homebrew、npm、pip、Cargo 和 Xcode 工具链明确属于缓存的数据。
- Homebrew `cleanup` 的 dry-run 输出中明确列出的缓存或旧版本。
- Xcode 未运行时，超过七天的 DerivedData 内容。

绿色缓存可以永久删除，因为它们必须具备可再生性。删除前仍需生成清理计划并重新验证路径、文件标识、所有者和应用运行状态。

### 3.2 黄色：必须确认

黄色项目包括：

- 置信度足够高的已卸载应用残留。
- Homebrew `autoremove --dry-run` 明确列出的未使用依赖。
- 包管理器或开发工具明确提供的其他可移除候选项。
- Xcode 不可用模拟器等可通过官方工具删除的开发资源。
- 需要管理员权限的白名单清理目标。

卸载残留默认移动到系统废纸篓。依赖卸载通过原包管理器执行，并在确认界面展示包名、依据、预计空间和实际命令预览。应用不会以管理员身份运行 Homebrew、npm、pip 或 Cargo。

### 3.3 红色：仅报告

以下项目不提供删除操作：

- 所有权或来源不明确的文件。
- 仍被已安装应用、项目环境或包管理器引用的内容。
- 解析后越出允许根目录的符号链接。
- 系统完整性保护范围和系统关键缓存。
- 用户文档、下载内容、照片、音乐及其他个人文件。
- 项目中的 `node_modules`、Python 虚拟环境、Rust `target` 目录。
- 只能根据访问时间猜测为“未使用”的依赖。

若 npm、pip 或 Cargo 没有提供权威的未使用依赖结果，第一版只处理其缓存，不自行推断全局或项目依赖。此限制是已确认安全规则的直接结果。

## 4. 候选项来源追踪和 Finder 定位

每个候选项必须记录并展示：

- 原始路径和规范化路径。
- 扫描器名称与发现规则。
- 所属应用名称、Bundle ID 或包管理器。
- 占用空间、修改时间和风险级别。
- 风险判断依据与计划执行的动作。
- 包管理器候选项对应的命令预览。

详情窗口的每个候选项提供“在 Finder 中显示”操作。应用使用 `NSWorkspace.activateFileViewerSelecting(_:)` 选中实际文件或目录；同一目录下的多个候选项可以一次定位。包管理器项目定位到实际安装目录、缓存目录或工具输出所指向的路径。

Finder 操作使用已经规范化并完成符号链接检查的 URL。路径不存在、无权访问或已被清理时，按钮禁用并说明原因。审计记录保留原始路径，但不会把已不存在的路径显示为可打开状态。

## 5. 应用架构

### 5.1 MacCleanApp

SwiftUI 主应用负责菜单栏弹窗、详情窗口、确认流程、设置、通知和首次权限引导。菜单栏弹窗只展示保护状态、预计可释放空间、待确认数量和“立即扫描”入口。

详情窗口按“安全缓存、应用残留、包管理器、开发环境、仅报告”分组展示候选项，并支持搜索、展开文件、Finder 定位和批量确认。

### 5.2 CleanCore

CleanCore 是独立 Swift Package，包含以下边界清晰的组件：

- `ScanCoordinator`：并发运行扫描器、汇总进度和部分失败。
- `Candidate`：统一候选项数据模型。
- `RiskClassifier`：根据证据和策略生成绿色、黄色或红色结论。
- `CleanupPlanner`：把候选项转换为不可变的执行计划。
- `CleanupExecutor`：执行普通用户权限范围内的文件操作和包管理器操作。
- `AuditStore`：保存本地扫描与清理记录。

界面不直接删除文件，扫描器也不直接删除文件。所有变更都必须通过 `CleanupPlanner` 和 `CleanupExecutor`。

### 5.3 独立扫描器

扫描器遵循统一协议，只负责发现候选项和提供证据：

- 应用缓存与日志扫描器。
- 卸载残留扫描器。
- Homebrew 扫描器。
- npm、pip、Cargo 缓存扫描器。
- Xcode 开发资源扫描器。

卸载残留扫描器枚举 `/Applications`、`~/Applications` 和 Launch Services 可见应用的 Bundle ID。只有残留标识可与缺失应用可靠关联、并且没有已安装应用声明同一标识时，才允许进入黄色分类。

包管理器扫描器优先使用机器可读输出；只能解析文本时，解析器按工具版本隔离并保存原始输出摘要。解析失败只使该扫描器降级，不阻断其他扫描器。

### 5.4 最小权限 XPC Helper

签名 Helper 通过 ServiceManagement 注册，并使用版本化 XPC 请求。它只接受固定操作枚举、规范化路径、预期文件标识和允许根目录标识，不接受任意 shell 命令或未验证的自由路径。

Helper 必须：

- 验证调用方代码签名和 XPC 审计身份。
- 拒绝符号链接越界、根目录本身、系统关键目录和不匹配的文件标识。
- 在操作前再次解析路径并检查目标未发生替换。
- 返回结构化结果，不拼接或执行 shell 字符串。

主应用仅在普通权限无法完成已确认的白名单动作时调用 Helper。系统完整性保护范围始终不处理。

### 5.5 调度、通知和持久化

应用通过 `SMAppService` 提供登录时启动选项。每周计划保存在本地；应用运行时到期执行，启动时发现过期则补扫。通知使用 UserNotifications。

扫描历史、候选项摘要、执行结果和设置保存在应用容器内的 SwiftData 存储中。数据不上传。审计记录保存路径是为了追踪和 Finder 定位；用户可以在设置中清空历史记录。

## 6. 数据流

1. `ScanCoordinator` 收集系统权限、运行应用、已安装应用和包管理器版本。
2. 独立扫描器产生候选项、路径、大小和来源证据。
3. `RiskClassifier` 结合证据、允许根目录和运行状态分类。
4. `CleanupPlanner` 生成包含前置条件的不可变清理计划。
5. 绿色计划可以自动执行；黄色计划进入确认界面；红色项目只显示。
6. 执行器在动作前重新验证规范化路径、文件标识、所有者和运行状态。
7. 普通文件操作由主应用执行；固定的受保护操作交给 Helper；依赖操作由原包管理器以当前用户身份执行。
8. 每项结果独立记录。单项失败不撤销已经成功的无关项目，也不继续执行依赖该项的后续动作。
9. 应用更新总计空间并发送通知。

## 7. 路径与并发安全

- 所有文件 URL 都先标准化并解析符号链接。
- 允许根目录使用组件级包含关系判断，不使用字符串前缀判断。
- 候选阶段记录资源标识、卷标识、所有者、大小和修改时间。
- 执行阶段重新打开目标并比对标识，防止扫描后替换和符号链接竞态。
- 拒绝删除卷根、用户主目录、允许根目录本身以及父级路径。
- 扫描期间应用退出或目标发生变化时，候选项重新分类或跳过。
- 正在运行应用的缓存不自动清理。

## 8. 错误处理和权限体验

- 未开启完全磁盘访问时，应用展示缺失覆盖范围，并提供前往系统设置的引导，不把“无法访问”解释为“没有垃圾”。
- 单个扫描器失败时显示该分类的错误和重试按钮，其他结果仍可使用。
- 包管理器不存在、版本不支持或输出无法解析时，明确显示“不支持此版本”，不猜测结果。
- Finder 路径失效时禁用定位操作。
- 清理前空间不足、磁盘卸载或权限变化时停止对应动作并保留候选项。
- Helper 拒绝请求时展示安全原因，不自动扩大权限或降级为 shell 命令。

## 9. 界面设计

菜单栏采用已确认的 A 方案：极简弹窗。主状态包括“受保护、正在扫描、需要权限、存在待确认项、部分扫描失败”。

详情窗口的候选项行展示名称、来源、路径摘要、大小、风险标签和选择框。展开后展示完整证据、实际路径、Finder 定位、命令预览和清理影响。危险动作不与普通导航按钮相邻。

所有界面支持浅色和暗黑模式，正文与背景文字对比度至少达到 WCAG AA 的 4.5:1。应用支持 VoiceOver 标签、键盘导航、动态字体和“减少动态效果”。

## 10. 测试策略

### 10.1 单元测试

- 候选项分类规则和降级规则。
- 规范化路径、允许根目录和符号链接越界。
- 扫描后文件替换、资源标识变化和应用运行状态变化。
- Bundle ID 残留关联与已安装应用排除。
- 各包管理器版本的固定输出样本解析。
- 清理计划依赖关系、确认要求和审计结果。
- Finder 定位在存在、缺失和无权限路径上的状态。

### 10.2 集成测试

- 在临时目录构造缓存、日志、残留和符号链接树，验证扫描到执行的完整流程。
- 使用受控假包管理器进程验证 dry-run、命令参数、退出码和异常输出。
- 主应用与 Helper 的签名校验、请求版本、白名单和拒绝路径。
- SwiftData 历史记录和每周调度补扫行为。

### 10.3 UI 与发布验证

- 菜单栏弹窗、详情分类、批量确认和 Finder 定位 UI 测试。
- 浅色、暗黑模式和辅助功能对比度检查。
- 未授权、部分授权和完全磁盘访问场景。
- Apple Silicon 与 Intel 构建、Hardened Runtime、Developer ID 签名、公证、Staple 和全新 Mac 安装验证。

任何清理功能和安全修复都采用测试先行：先构造能复现风险或目标行为的失败测试，再实现最小代码使其通过。

## 11. 验收标准

- 用户可以从菜单栏启动扫描并查看总空间和待确认数量。
- 每周扫描可在错过时间后补执行，并且只自动处理绿色项目。
- 每个候选项都有来源、理由、路径和风险等级。
- 可用候选项可以在 Finder 中直接定位；失效候选项给出明确状态。
- 卸载残留不会与仍安装应用的 Bundle ID 冲突。
- 未使用依赖只来自包管理器的权威结果。
- 任何符号链接越界、路径替换、根目录目标或非白名单 Helper 请求都被拒绝。
- 一项扫描或清理失败不会破坏其他独立结果。
- 应用不上传扫描数据，并允许用户清除本地历史。
- 通用版本能够完成签名、公证并从 `.dmg` 正常安装。

## 12. 第一版不包含

- Mac App Store 发布。
- 重复文件、相似照片和大文件管理。
- 自动卸载 `.app` 本体。
- 清理用户文档或项目工作区。
- 根据最后访问时间推断未使用依赖。
- 绕过系统完整性保护或清理系统关键缓存。
- 云端账户、遥测或跨设备同步。
